## Implementation issues

### CRITICAL — Blocking

**[tests/utils/__init__.py] Package shadowing makes all `tests/utils/` imports fail**

`tests/utils/__init__.py` exists as an empty file, causing Python to treat `tests/utils/` as a package
named `utils`. When pytest runs any test under `tests/utils/`, the `from utils.llm import LLMClient`
etc. resolve to `tests/utils/llm` (not found) rather than `backend/utils/llm`. All 34 tests in
`tests/utils/` fail with `ModuleNotFoundError: No module named 'utils.llm'` (or `utils.pdf`,
`utils.firebase`).

Additionally, `tests/conftest.py` line 13 does `from routes import all_blueprints` — but because
`tests/routes/__init__.py` also exists, pytest's sys.path at conftest load time resolves `routes` to
`tests/routes/` (which does not export `all_blueprints`), causing `ImportError`. **This breaks the
entire test suite** when running `pytest` without `--noconftest`.

Fix: Add `pythonpath = ["."]` to `pyproject.toml` under `[tool.pytest.ini_options]`, and remove or
rename `tests/utils/__init__.py` so it is not treated as a package (or switch to namespace packages via
`conftest.py`-based path insertion only).

### MODERATE — Specification deviations

**[utils/firebase.py:101] Function renamed from `save_simplify_output` to `save_care_plan_output`**

The PRD (§4.3) specifies the function as `save_simplify_output`. The implementation uses
`save_care_plan_output` throughout. This is a coordinated rename that aligns with SP2's
`simplify → care_plan` rename, but it deviates from the SP3 spec without documenting the change. All
callers (`routes/batch.py:14`, `routes/care_plan.py:34`) and all tests already use the renamed form,
so there is no import breakage — but the spec contract is violated.

**[utils/firebase.py] `_without_raw` helper is missing**

The PRD (§4.3, Task 2 step 5) explicitly says to move `_without_raw` verbatim from `utils/save_output.py`
into `utils/firebase.py`. It is not present. The current `save_care_plan_output` writes `output_data`
directly without stripping `raw`. The original `save_simplify_output` used `_without_raw` to strip
the raw LLM text before Firestore persistence.

Impact: Either (a) the Firestore writes now include `raw` content that was previously stripped, or
(b) stripping has been moved to the caller (the route). The test at
`tests/utils/test_save_output.py:41-46` confirms `raw` is preserved in the payload
(`self.assertIs(payload["output_data"], output_data)` and checks `output_data["care_plan"]["raw"]`
exists) — i.e. the test was updated to expect no stripping. This is a behavioral change from the
original spec that needs explicit sign-off.

**[tasks/TASKS.md Task 8] `upload_combined_pdf` landed in `routes/care_plan.py`, not `routes/simplify_v1_2.py`**

TASKS.md Task 8 says: move `upload_combined_pdf` into `routes/simplify_v1_2.py`. It landed in
`routes/care_plan.py` (line 69). This is a consequence of SP2's route rename (the v1_2 route became
`care_plan.py`), so functionally correct — but the patch targets in test files correctly reflect the
new path (`routes.care_plan.upload_combined_pdf`), not the TASKS.md path.

### MINOR

## Summary

SP3's structural work is complete: all dead modules deleted, all three consolidation modules
(`utils/pdf.py`, `utils/firebase.py`, `utils/llm.py`) created, all import sites updated. The
blocking issue is the test infrastructure: `tests/utils/__init__.py` causes a package name collision
that makes every test in `tests/utils/` fail with import errors, and a related `tests/routes/__init__.py`
collision breaks the shared `conftest.py`. Until `pyproject.toml` adds `pythonpath = ["."]` and the
`__init__.py` files in test subdirectories are removed (or tests migrated to use namespace packages),
none of the Task 10 tests can be confirmed green. Two behavioral deviations from spec need explicit
sign-off: the `save_simplify_output` → `save_care_plan_output` rename (coordinated with SP2, appears
intentional) and the removal of `_without_raw` stripping (changes what is persisted to Firestore).
