## Implementation issues

No bugs found. The following are minor observations:

- **[`src/utils/normalizeOutput.ts:13`] Fast-path skips validation.** `if (!isLegacyShape(raw)) return raw as CarePlanInternal;` casts any object that has a `care_plan` key directly to `CarePlanInternal` without validating structure. This is intentional and consistent with pre-SP5 behavior (live envelope is trusted from the backend). No change needed; flagged for SP6 test awareness.

- **[`src/pages/care-plan/CarePlanPage.tsx:160`] `X-Trace-Id` handling in batch path only logs, does not propagate.** Both the single-run (line 268) and batch (line 160) paths log `traceId` via `logger.info('care_plan_request', { traceId })` but do not call any trace-propagation method (correct — `logger` has no `setTraceId`). This matches PRD §4.7 exactly. SP4 owns whether a `setTraceId` API is added to `logger`.

- **[`src/components/OutputGradingCard.tsx:39-40`] `X-Trace-Id` not read on grade endpoint.** The PRD §4.7 says "Also apply to `OutputGradingCard.tsx`'s `/care_plan/grade` fetch (read `X-Session-Id` after `res.ok`)." Only `X-Session-Id` is read in `OutputGradingCard.tsx` — `X-Trace-Id` is not. This is defensible (the PRD text only explicitly lists `X-Session-Id` for `OutputGradingCard`), but the pattern in `CarePlanPage.tsx` reads both. Minor inconsistency.

## Test coverage gaps

The test suite has 63 passing tests. The following gaps remain (consistent with SP6 ownership per PRD §7):

4. **`router.test.ts` was deleted** (correct per Task 2) but no SP6 replacement has been added yet. `router.tsx` now only exports `VersionRouteState` (an interface), so a test may not be needed; worth confirming in SP6.

5. **`api/datasets.ts` has no test file.** `listDatasets`, `getDatasetFileContent`, and `runBatch` are untested. Not called out in PRD §7 but a natural gap alongside the `savedOutputs.test.ts` coverage.
