## Implementation issues

### Critical — Blocks all pytest runs

- **`backend/pyproject.toml`** (no `pythonpath` key) + **`tests/routes/__init__.py`** (empty) + **`tests/utils/__init__.py`** (exists):
  When pytest runs, it adds `tests/` to `sys.path` because `tests/utils/` is a Python package
  (has `__init__.py`) and `tests/` is its parent. This makes `import routes` resolve to
  `tests/routes/` (empty `__init__.py`) instead of `backend/routes/`. `conftest.py:13`
  (`from routes import all_blueprints`) then fails with `ImportError: cannot import name
  'all_blueprints' from 'routes'`, which terminates the entire pytest session before any test
  is collected.

  **Fix (choose one):**
  - Add `pythonpath = ["."]` to `[tool.pytest.ini_options]` in `pyproject.toml` — this
    ensures `backend/` is inserted first.
  - Or move the `sys.path` manipulation in `conftest.py` above the `from routes import …`
    line — it already does this (lines 7–9 insert BACKEND_DIR first) but Python's conftest
    discovery inserts `tests/` before conftest runs.
  - Or delete `tests/routes/__init__.py` to de-package that directory so it doesn't shadow
    `backend/routes/` on sys.path.

  **All tests were verified to pass when run with `PYTHONPATH=/root/projects/juno/backend`
  or via `sys.path.insert(0, "/root/projects/juno/backend")` — the logic is correct.**

### Minor — Spec deviation (non-security)

- **`routes/care_plan.py:521`** and **`routes/batch.py:185`**:
  Both use `getattr(g, "session_id", "")` instead of `g.session_id` as Task 6 specifies.
  The security bug (using `user_id` as fallback) is fixed; using an empty-string fallback
  instead of direct attribute access is harmless since `before_request` always sets
  `g.session_id`. Still, it is inconsistent with the task spec and leaves defensive code
  that masks a broken middleware chain.

### Informational — JunoMetrics module still on disk

- **`backend/utils/juno_metrics.py`**: The module is retained on disk. PRD §9.1 says SP3
  deletes it; SP4 only removes call sites. No production code imports it (confirmed: only
  self-reference in its own docstring). This is expected — SP3 owns this deletion. Flagging
  it so the SP3 handoff is explicit.

### Informational — Duplicate test files

- **`tests/test_markers.py`** (169 lines) is byte-identical to `tests/utils/test_code_markers.py`.
- **`tests/test_sp4_*.py`** files are near-identical to `tests/utils/test_*.py` with different
  path calculations (one level shallower). These appear to be leftover TDD-phase drafts. They
  cause no harm but add noise. Recommend deleting `tests/test_markers.py` and `tests/test_sp4_*.py`
  in a cleanup pass.

### Informational — `execute_async` not tested

- `execute_async` is implemented in `marker.py` but has no test coverage. Per PRD §9.4
  (RESOLVED: KEEP async), this is intentional. No action required.

## Summary

The SP4 observability implementation is functionally complete and correct:

- The `utils/markers/` package faithfully ports the sample's `CodeMarker`, `Scope`, `@code_marker`,
  `execute`/`execute_async`, `InMemorySink`, `ConsoleSink`, and adds `JunoSink` and `JunoContext`
  as specified.
- All 9 marker leaves in the `Markers` registry emit the correct metric names.
- `JunoSink` correctly emits two log lines per event (metric + timeline), with proper ERROR level
  on failure.
- `JunoContext.from_g` reads all standard dimensions from `flask.g` and handles out-of-request
  context gracefully.
- The care-plan pipeline replaces all stopwatch boilerplate with `.execute()` wrappers across all
  7 steps; non-fatal steps use `scope.mark_failed()` + fallback; LLM steps wrap manual OTel child
  spans.
- `JunoLogger` drops `api_version` / `log_step` and gains `function` + three version fields.
- `StructuredJsonFormatter` correctly serializes all whitelisted extra keys including boolean
  `False` (sentinel check rather than truthiness).
- `SERVICE_VERSION` has a code-derived default via `backend/VERSION` (`1.2.0`).
- `X-Trace-Id` header set in `after_request` and exposed via CORS.
- `docs/logging.md` is complete.

**Blocking issue: the pytest infrastructure is broken** — `tests/routes/__init__.py` being an
empty Python package file shadows `backend/routes/`, causing `conftest.py` to fail on import.
No tests can be collected via `pytest`. Fix: add `pythonpath = ["."]` to `pyproject.toml`, or
delete `tests/routes/__init__.py`.
