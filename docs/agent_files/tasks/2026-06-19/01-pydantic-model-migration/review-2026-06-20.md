## Implementation issues

### Critical — Blocks `pytest tests/models/` from running

**Issue 1: `pyproject.toml` missing `pythonpath = ["."]`**

`/root/projects/juno/backend/pyproject.toml` has no `pythonpath` entry in
`[tool.pytest.ini_options]`. When pytest runs from `backend/` with `testpaths = ["tests"]`, it
inserts the `tests/` directory into `sys.path` for package resolution. Because
`tests/models/__init__.py` exists (an empty file), Python resolves `import models` to
`tests/models/` — the empty stub — rather than `backend/models/`. This causes every test in
`tests/models/` to fail with `ModuleNotFoundError: No module named 'models.base'`.

Fix: add `pythonpath = ["."]` to `[tool.pytest.ini_options]` in `pyproject.toml`.

**Issue 2: `conftest.py` imports from a shadowed `routes` package**

`/root/projects/juno/backend/tests/conftest.py:13` does `from routes import all_blueprints`.
Because `tests/routes/__init__.py` exists as an empty file, `routes` resolves to `tests/routes/`
(empty) instead of `backend/routes/`, causing `ImportError: cannot import name 'all_blueprints'`.
This fires before any test is collected, making `python -m pytest tests/models/ -v` exit with
code 4 immediately.

Fix: either (a) add `pythonpath = ["."]` to `pyproject.toml` (same fix as Issue 1, since
`backend/` would then be found first), or (b) delete the empty `tests/routes/__init__.py` and
`tests/models/__init__.py` if they are not needed as namespace packages.

### Minor — Unnecessary custom field validator/serializer on `CarePlanInternal`

`/root/projects/juno/backend/models/envelope.py` defines a `@field_validator("care_plan",
mode="before")` and a `@field_serializer("care_plan")`. The validator handles the
`dict -> CarePlan` coercion on `from_dict`, and the serializer forces `.to_dict()` on output.
This works correctly (verified by tests), but the validator is redundant: Pydantic v2's
`model_validate` already handles nested model coercion from dicts if the field type is a
`BaseModel` subclass (via implicit dict coercion). The serializer is needed only because Pydantic
would otherwise call `.model_dump()` which skips the versioned dispatch. The current approach is
sound but introduces complexity that should be documented with a comment explaining why the
serializer is required (the `CarePlan` field is a family-base polymorphic type, so standard
`model_dump` would not capture the concrete subclass's extra fields correctly without the
serializer). No behavior bug — just a clarity concern.

### Minor — Test file duplication

Tests exist in two locations:
- `tests/models/test_*.py` (7 files — the SP1 canonical location)
- `tests/test_models_*.py` (root-level older copies, e.g. `tests/test_models_envelope.py`,
  `tests/test_models.py`, `tests/test_care_plan_route_module.py`)

The root-level copies appear to be legacy files that may conflict or double-run. This is a SP6
concern (test reorg), but it is worth noting that `tests/test_models_envelope.py` and
`tests/models/test_envelope.py` are near-identical, which could cause confusion.

## Summary

The SP1 Pydantic Model Migration is functionally complete and architecturally correct. All seven
model files (`base.py`, `care_plan.py`, `envelope.py`, `grading.py`, `input.py`, `metrics.py`,
`__init__.py`) are rewritten in Pydantic v2 with `extra="forbid"` on every model, correct
`model_dump(mode="json")` / `model_validate` API usage, the `care_plan` wire key hard-flipped, `raw`
preserved and saved, `appointment.schema.json` deleted, the LLM schema generated from
`CarePlanV1_2StructuredLLM.model_json_schema()`, `V1_2Pipeline.run()` returning a typed
`CarePlanV1_2`, all version constants exposed, and all old `SimplifyOutput`/`SimplifiedCarePlan`
aliases removed. Every individual test assertion passes when run with the correct `sys.path`.
The single blocking issue is a `pyproject.toml` misconfiguration: missing `pythonpath = ["."]`
under `[tool.pytest.ini_options]` causes both the `conftest.py` and the `tests/models/` package
to resolve the wrong `routes` and `models` packages during collection, making `pytest tests/models/`
exit with code 4 (collection error) before a single test runs. Adding one line to `pyproject.toml`
fixes this and allows the full test suite to execute.
