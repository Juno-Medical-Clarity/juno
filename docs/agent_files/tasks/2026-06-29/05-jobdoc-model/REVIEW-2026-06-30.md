test-isolation / missing-export bugs surfaced (not caused) by the full-suite run,
and the run summary discloses them. `routes/care_plan.py` is the only non-test
production file touched (a one-line `CARE_PLAN_VERSION` import). Low risk; flagged
only for transparency. No action required.

### Non-issues confirmed (not defects)
- "29 vs 31 fields": the PRD field table actually enumerates all 31 fields
  (including `stage` and `started_at`); the "29" figure in a couple of prose
  lines is a miscount. Model is correct.
- Import path: TASKS' illustrative `from .envelope import CarePlanInternal` is
  realised as the correct `from .care_plan.envelope import CarePlanInternal`
  (`job.py:11`) since `envelope` lives under `models/care_plan/`. Correct as built.
- `ErrorDetail` inherits `extra="forbid"`; a malformed out-of-band `error_data`
  blob would raise in `from_firestore()`. This is mitigated by the worker's
  `execute_job` try/except → `fail_job`, and `build_error_data` output is verified
  compatible by `test_error_data_typed_submodel`. Acceptable per TASKS note.
