## BLOCKER found during final verification (this run is NOT fully clean)

`npm run build` (`tsc -b && vite build`), required by TASKS.md's own Verification §3, fails
on the current branch HEAD (`2a236f47`):

```
src/pages/care-plan/CarePlanJobPage.tsx(55,10): error TS2352: Conversion of type
'Record<string, unknown>' to type 'CarePlanInternal' may be a mistake because neither type
sufficiently overlaps with the other. If this was intentional, convert the expression to
'unknown' first.
  Type 'Record<string, unknown>' is missing the following properties from type
  'CarePlanInternal': metrics, input, grading, care_plan
```

**Root cause:** Task 10.5's direct cast `(jobDoc.output_data as CarePlanInternal)` — copied
verbatim from the PRD's own §4c suggested code — is rejected by TypeScript because
`JobDoc.output_data` is typed `Record<string, unknown> | null` (see
`frontend/src/hooks/useJobSnapshot.ts:12`), which the compiler considers to not "sufficiently
overlap" with the concrete `CarePlanInternal` shape for a single-step `as` cast. The fix
TypeScript itself suggests is a double cast through `unknown`:
`(jobDoc.output_data as unknown as CarePlanInternal)`.

**Why this wasn't caught during Task 10.5's own verification:** the sub-agent (and all other
sub-agents in this run) ran `npx tsc --noEmit` from `frontend/` with no `-p`/`-b` flag. This
repo's root `frontend/tsconfig.json` has `"files": []` and only `references` to
`tsconfig.app.json`/`tsconfig.node.json` — running bare `tsc --noEmit` against it is a
**no-op that type-checks zero files** (confirmed directly: `npx tsc --noEmit --listFiles`
prints 0 lines). Every "tsc --noEmit passes" claim across all 7 tasks in this run was
therefore not actually validating anything. The real check is `npx tsc -b` (used by
`npm run build`) or `npx tsc --noEmit -p tsconfig.app.json` directly — both of which I ran
myself during final verification and both reproduce the TS2352 error above.

I confirmed this is a genuine regression, not pre-existing: I built a clean worktree at the
pre-SP10 commit (`17d3a74b`) and ran `npm run build` there — it succeeds cleanly (Vite build
completes, 103 modules transformed, no tsc errors). The break is introduced by Task 10.5
(commit `e31ec52f`) and persists through Tasks 10.6/10.7 on top of it.

**`npm run lint`** also reports 12 pre-existing problems (8 errors, 4 warnings) — verified
identical on both the pre-SP10 baseline (`17d3a74b`) and the current HEAD, so this is **not**
a regression from SP10 and is out of scope for this run (noted under Follow-ups).

**Why I stopped here instead of pushing a fix:** per this run's mandate, a genuine
implementation/test failure discovered during verification means stop, document, and do not
pile on more commits or skip ahead. The fix itself is small and well-understood (change the
single-step cast to a double cast through `unknown` in
`frontend/src/pages/care-plan/CarePlanJobPage.tsx` line 55), but it is not something I
authored or dispatched a sub-agent to do in this run — it needs to land as its own
reviewed, test-driven commit (and the verification command used by future SP10/frontend work
should be corrected to `npx tsc -b` or `-p tsconfig.app.json`, not bare `tsc --noEmit`).
