## Follow-ups / new issues discovered

Ranked recommendations from `../optimization-findings-2026-09-05.md` deliberately **not**
implemented in this pass (per PRD §3 Non-Goals and §4.4):

- **#4 — Skip computing the unused non-`combined` grading methods, not just storing
  them.** Not recommended standalone: the textstat calls being skipped are cheap
  (likely low-single-digit ms each, tens of ms total per job), and doing this safely
  requires a real conditional inside `models/grading.py`'s
  `build_grading_with_before_after_score`, which the main app's own grading route/UI
  also depends on — a higher-risk change for a low-confidence, small saving already
  dwarfed by Task 1's payload win.
- **#5 — Drop `low_priority` from the trial's structuring-step JSON schema/prompt.**
  Not recommended: it's the smallest-impact item found (≈1–3% of one pipeline step's
  tokens), but removing the field from the schema without also removing the prompt's
  rule 11 ("put low-priority details in low_priority array") risks the model stuffing
  that content into `diagnosis`, `other`, or `summary` instead — a real output-quality
  regression risk for disproportionate plumbing effort (two schema variants, two prompt
  variants, threaded through four call layers).
- **#6 — Move OCR/text extraction off the synchronous `POST /trial/jobs` request path.**
  Flagged but explicitly not trial-scoped: `routes/care_plan_jobs.py` has the identical
  synchronous-extraction pattern for the main app's logged-in image uploads, so fixing
  this only for the trial would diverge trial and main-app input handling; recommended
  (in the findings doc) as a separate, deliberately shared-scope initiative if ever
  pursued, not part of a trial-optimization pass.

No new issues were discovered during implementation or this verification run.
