## Accepted limitations

- The rate limiter buckets by wall-clock hour, so up to 10 requests can land within seconds across an hour boundary. A true sliding window would need a second Firestore read per request or a changed counter-document shape; deferred deliberately.
- `useUnloadCleanup` deletes the job on `visibilitychange → hidden`, so backgrounding a tab mid-processing loses that in-flight job. This is the PRD's explicit choice (§4.13) for mobile Safari reliability; the worker handles the missing doc gracefully.
- SP5's Q5 (persisted cursor) and Q6 (overlap lock) remain deferred and unimplemented.
- `frontend/`'s `npm run lint` has 8 pre-existing errors (in `AuthContext.test.tsx` and `vite.config.ts`) that predate this branch; `ci.yml` runs tests, not lint, for both frontend jobs.
